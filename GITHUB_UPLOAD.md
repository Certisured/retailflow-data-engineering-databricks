# Upload this starter to Certisured GitHub

Recommended dedicated repository name: `retailflow-data-engineering`.

1. Extract `retailflow-starter-repo-v1.0.0.zip` on your computer. Open the extracted folder. You should see README.md immediately alongside notebooks/ and retailflow-v1.0.0/.
2. Open your intended public Certisured GitHub repository. If this is a new dedicated repository, the extracted contents belong at its **root**.
3. Choose **Add file → Upload files**. Drag **all the contents inside the extracted folder** into the upload area, preserving the folders. Include .gitignore and .gitattributes. Do not drag the enclosing starter-folder itself and create an extra nested level.
4. Review the uploaded file list. README.md should be at the repository root, and one example source path should be retailflow-v1.0.0/data/sales_batch_01.csv.
5. Use a message such as `Add RetailFlow learner starter v1.0.0`. Complete the commit or pull-request flow offered for your repository; if a pull request is required, merge it before sharing the learner link.
6. Confirm that the root README displays and the repository is public. Share its exact repository URL for verification. Record the final commit SHA so course instructions can reference an immutable version.

Upload the **extracted files**, not only the ZIP. Keeping only a ZIP prevents the expected file paths and notebook checkpoints from being directly visible. Keep the earlier dataset ZIP, instructor-notebook ZIP and playlist-authoring ZIP out of this public starter; this package already contains the intended learner materials.

If your repository already contains unrelated work or another README, use a dedicated course repository or reconcile those files before committing. Do not replace unrelated content blindly. A subfolder deployment changes learner paths and must be agreed before Build Buddy is finalized.

GitHub supports dragging files or folders into its uploader and allows up to 100 files at once, with a 25 MiB limit per browser-uploaded file. This package is below both limits. See [GitHub's upload instructions](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

After you share the public URL, verify the root layout, direct CSV access, notebook structure, empty exercise cells, learner-only content, checks/expected paths, version/hash manifests and the downloadable repository archive before using the URL in Wizori.
